# Email Templates

All SmartQueue email is branded and mobile-responsive: a dark header with the SmartQueue wordmark, a white content card, a single accent-colored button, and a footer linking back to [smart-queue.in](https://smart-queue.in). Layout uses a table-based structure (so it renders correctly in Outlook) plus a `@media (max-width: 480px)` query that tightens padding and stacks the button full-width on phones.

Files live in [docs/emails/](emails/).

## Supabase Auth Templates (copy-paste into the Supabase dashboard)

Go to **Supabase Dashboard → Authentication → Emails**, open each template tab, and paste the matching file's HTML into the **Message body** field (switch to the HTML/code editor if the dashboard defaults to the visual editor).

| Template file | Supabase tab | Sent when | Variables |
|---|---|---|---|
| [confirm-signup.html](emails/confirm-signup.html) | Confirm signup | A new user signs up with email + password | `{{ .ConfirmationURL }}` |
| [magic-link.html](emails/magic-link.html) | Magic Link | A user requests email OTP / magic-link sign-in | `{{ .ConfirmationURL }}` |
| [reset-password.html](emails/reset-password.html) | Reset Password | A user clicks "Forgot password?" | `{{ .ConfirmationURL }}` |

Don't change the `{{ .ConfirmationURL }}` placeholders — Supabase substitutes them at send time. The app doesn't expose an email-change flow, so Supabase's "Change Email Address" template is left as default; "Invite user" and "Reauthentication" are likewise untouched since the app doesn't use them either.

These three are sent directly by Supabase (or by your configured SMTP provider through Supabase), not by our backend — pasting the HTML into the dashboard is a one-time manual step, not something the codebase can push automatically.

## App Email Templates (already wired into the backend — reference only)

These are generated by `EmailService.java` via the shared `wrap()` template helper, not pasted anywhere. The files below show exactly what gets sent, with `{{placeholders}}` standing in for the real values the backend fills in.

| Template file | Backend method | Sent when |
|---|---|---|
| [welcome.html](emails/welcome.html) | `sendWelcomeEmail` | A user's Supabase identity is synced to the backend for the first time |
| [sign-in-alert.html](emails/sign-in-alert.html) | `sendSignInNotification` | Every sign-in after the first (password, OTP, Google, or admin) |
| [token-created.html](emails/token-created.html) | `sendTokenCreated` | A user generates a new token |
| [token-cancelled.html](emails/token-cancelled.html) | `sendTokenCancelled` | A user cancels their own waiting token |
| [token-skipped.html](emails/token-skipped.html) | `sendTokenSkipped` | An admin skips a called/serving token |
| [token-completed.html](emails/token-completed.html) | `sendTokenCompleted` | An admin marks a token as completed |
| [turn-reminder.html](emails/turn-reminder.html) | `sendTurnReminder` | A token's estimated wait drops to 5 minutes or less (once per token) |

To change copy or styling for these, edit `wrap()` and the `send*` methods in `backend/src/main/java/com/smartqueue/service/EmailService.java` — the files here exist for design reference, not as a separate source of truth.
